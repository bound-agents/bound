---
title: Create a webhook
description: Receive signed HTTP events and process each delivery as a Bound task.
---

Use a webhook when an external service should push an event to Bound. Bound validates the
request, deduplicates supported delivery identifiers, and wakes the linked event task.

## Prerequisites

- A running Bound instance
- A sync-server URL that the external service can reach
- Access to configure the external service

## Create the webhook in the web UI

1. Open **Connections > Webhooks**.
2. Select **Create**.
3. Enter a unique name and choose a signature format.
4. Set any custom prompt, model hint, or history option.
5. Save the webhook and record the generated secret.

The secret is shown when the webhook is created. Store it where you configure the sending
service.

## Create the webhook through the API

```bash
curl -X POST http://localhost:3001/api/webhooks \
  -H "Content-Type: application/json" \
  -d '{
    "name": "github",
    "format": "github",
    "description": "GitHub push events"
  }'
```

## Choose a signature format

| Format | How it validates | Use case |
| --- | --- | --- |
| `github` | HMAC-SHA256 of the payload body, sent in `X-Hub-Signature-256` | GitHub webhooks |
| `stripe` | HMAC-SHA256, sent in `Stripe-Signature` header | Stripe events |
| `slack` | HMAC-SHA256, sent in `X-Slack-Signature` | Slack slash commands / events |
| `raw` | HMAC-SHA256 over the timestamp and body, sent in `X-Webhook-Signature` with `X-Webhook-Timestamp` | Custom integrations |
| `none` | No signature validation | Unauthenticated integrations |

:::danger[Unauthenticated deliveries]
The `none` format accepts requests without authentication. Bound rejects creation and
delivery for this format unless the cluster-wide unauthenticated-webhook switch is enabled.
Only enable it behind a network boundary that prevents untrusted requests.
:::

Enable the switch in **Connections > Webhooks** or through the API:

```bash
curl -X PUT http://localhost:3001/api/webhooks/unauthenticated-switch \
  -H "Content-Type: application/json" \
  -d '{"allow_unauthenticated": true}'
```

## Configure the delivery URL

Webhook delivery uses the sync server, which listens on port `3000` by default. The web UI
lists the valid URLs for the current cluster.

```text
http://your-hub-host:3000/webhook/github
```

If a reverse proxy fronts the hub, route this path to the hub's sync server rather than the
web API on port `3001`.

### GitHub

1. Open **Settings > Webhooks > Add webhook** in the repository.
2. Set **Payload URL** to the Bound delivery URL.
3. Set **Content type** to `application/json`.
4. Enter the secret generated by Bound.
5. Select the events to deliver.

### Provider-specific formats

The `stripe` and `slack` formats validate those providers' standard signature
headers. The secret stored by Bound must match the secret used by the sender.
Bound currently generates this value when the webhook is created, so use these
formats only with senders that can use the generated secret.

Stripe, Slack, and raw signatures must include a timestamp within five minutes
of the receiving host's clock.

## Verify delivery

Send a test event from the external service. Confirm that the webhook detail view shows the
delivery and that its linked task runs.

Bound deduplicates deliveries that include `X-GitHub-Delivery`,
`Stripe-Idempotency-Key`, or `X-Idempotency-Key`.

## Managing webhooks

Use **Connections > Webhooks** to edit settings, rotate a secret, inspect deliveries, or
delete a webhook.

The API provides `GET /api/webhooks`, `GET /api/webhooks/:id`,
`PATCH /api/webhooks/:id`, and `DELETE /api/webhooks/:id`.
