## Human Verification

| AC | Justification | Verification Approach |
|---|---|---|
| §8.5 gate: 7-day post-rollout `consecutive_failures` window ≤ 1.2× baseline | Requires production telemetry across a 7-day window. The metric is collected by the live scheduler against the running `tasks` table; cannot be reproduced in CI without the underlying production task workload, the production user's interaction patterns, and the 7-day clock window. | Operator queries the production database for `SELECT AVG(consecutive_failures) FROM tasks WHERE deleted = 0 AND created_at >= ? AND created_at < ?` across the 7-day pre-rollout window and the 7-day post-rollout window, then asserts `post_mean ≤ 1.2 × pre_mean`. The pre-rollout baseline is captured at rollout time and pinned to the rollout's deploy log. |
| §8.5 gate: §8.6 behavioral probe results interpretation (operator review of probe metrics) | The probe is automated (Phase 7 Task 4) but the acceptance gate evaluation is a one-time post-rollout review of a probe run's `content_pct` / `disclaimer_pct`, not a per-PR CI gate. Per Phase 7 Task 5 and spec §8.6 closing paragraph, the probe runs on a separate weekly cadence (operator-run `behavioral-probe.yml`) and consumes inference budget; the per-PR suite skips it via `BOUND_RUN_BEHAVIORAL_PROBE` default-off. The numeric thresholds are checked by the test code, but the decision to merge or revisit on borderline `content_pct ∈ [0.6, 0.8]` is operator judgement informed by the §8.6 "between 0.5 and 0.8 → revisit" clause. | Operator reads the `content_pct` and `disclaimer_pct` from the most recent `behavioral-probe.yml` workflow run's job logs (or a local `BOUND_RUN_BEHAVIORAL_PROBE=1 bun test packages/agent/src/__tests__/probes/` invocation), confirms post-RFC `content_pct ≥ 0.8` and `disclaimer_pct ≤ 0.2`, and pre-RFC control `disclaimer_pct ≥ 0.8`. For `content_pct ∈ [0.6, 0.8]`, operator re-runs the probe at N=20 per spec §8.6 and revisits the RFC if the second run still falls in the borderline band. |
